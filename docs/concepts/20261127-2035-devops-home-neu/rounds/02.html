Wozu devops Home?
Dein Startpunkt für devops: was auf dich wartet, wie viel Budget bleibt, und alle devops-Einstellungen an einem Ort.

Der Ausgabestil hängt am devops-Schalter, und wer Home zum ersten Mal öffnet, bekommt keine Erklärung.

Beides gilt in allen drei Köpfen gleich und entscheidet, was Home speichert und zeigt.

6 Fragen
Ausgabestil Einführung

≈ 3 min

Der Stil soll eine eigene Einstellung werden, unabhängig vom ⏻. Die Einführung ist neu und erklärt beim ersten Öffnen, was sich nicht von selbst erschließt.

Der Stil springt beim Projekt-Aus auf Standard.

Quiet regelt allgemeine Antwortregeln und die devops-Teile obendrauf. Nur die devops-Teile brauchen devops.

Gilt für: Ausgabestil auf allen Ebenen

Wer devops abschaltet, verliert auch die kurzen Antworten, obwohl diese Regeln devops gar nicht brauchen.

Stimmt das: Ausgabestil ist eine eigene Einstellung, Quiet wirkt auch ohne devops?

Quiet trägt zwei Schichten, nur eine braucht devops.

Quiet trägt zwei Schichten: allgemeine Antwortregeln und die devops-Teile obendrauf.

Ausgabestil Quiet
  immer:           kurz antworten · Sprache halten · keine Erzählung
  nur mit devops:  Abschlusskarte · Konzeptseiten-Regeln · Thread-Kanäle

devops aus  →  Quiet wirkt weiter, ohne die devops-Teile
devops an   →  Quiet plus devops-Teile

Gilt für: Ausgabestil

Liegt der Stil je Projekt, antwortet Claude in jedem Repo anders, ohne dass es auffällt.

Wo speichert Home den Ausgabestil?

Die Projektdatei gewinnt über die Benutzerdatei.

Claude Code liest ihn aus Benutzer- und Projektdatei, die Projektdatei gewinnt.

~/.claude/settings.json        "outputStyle": "Quiet"     → alle Projekte
.claude/settings.local.json    "outputStyle": "Standard"  → nur dotclaude, gewinnt

Gilt für: Projekt-Ebene

Wer ein Projekt abschaltet, bekommt dort wieder lange Antworten, weil der Stil mitspringt.

Soll das Projekt-Aus den Ausgabestil künftig unangetastet lassen?

Das Projekt-Aus setzt den Stil zurück.

Beim Einschalten holt devops den gemerkten Stil zurück.

Heute (scripts/devops-optout.js)
  Projekt aus  →  Ausgabestil: Standard   (gemerkt: Quiet)
  Projekt an   →  Ausgabestil: Quiet

Neu
  Projekt aus  →  Ausgabestil: Quiet      (devops-Teile ruhen)
  Projekt an   →  Ausgabestil: Quiet

Fünf Funktionen erklären sich nicht von selbst.

Die Einführung zeigt sie einmal als Tour über Home. Überspringen geht jederzeit, wiederholen über Hilfe.

Gilt für: Einführung

Fünf Funktionen von Home findet man nur durch Ausprobieren, keine erklärt sich beim ersten Öffnen.

Was erklärt die Einführung?

Mehrere Antworten möglich.

Fünf Funktionen findet man nur durch Ausprobieren.

Ein sechster Punkt gilt nur, wenn Claude-Projekte eingeschaltet sind.

Heute   erstes Öffnen → Home, kein Hinweis

Neu     1 von 5  Wozu devops Home?
        2 von 5  ⏻ schaltet Sitzung, Projekt oder alle Projekte
        3 von 5  👉 2 Öffnen springt direkt in die Sitzung
        4 von 5  🛏 schaltet den PC aus, wenn nichts mehr arbeitet
        5 von 5  ＋ Batch sammelt Notizen für einen Start

Gilt für: Einführung

Eine Einführung, die nach jedem Update wiederkommt, wird weggeklickt; eine, die nie wiederkommt, verpasst neue Funktionen.

Wann zeigt Home die Einführung von selbst?

Zu oft wird sie weggeklickt, zu selten verpasst sie Neues.

Wiederholen lässt sie sich jederzeit unter Hilfe.

Erstes Öffnen                      → Tour 1 von 5
„Überspringen“ oder letzter Schritt → kommt nicht mehr von selbst
Hilfe › Einführung erneut zeigen   → Tour von vorn

Gilt für: Einführung

Wer in jedem neuen Repo dieselbe Tour wegklicken muss, überspringt sie bald ungelesen.

Wofür merkt sich Home, dass die Einführung erledigt ist?

Eine Tour je Repo wird bald ungelesen übersprungen.

Die Tour erklärt Home, nicht das Projekt.

Pro Computer:  dotclaude  Tour ✓   →  hearthbot  keine Tour
Pro Projekt:   dotclaude  Tour ✓   →  hearthbot  Tour von vorn
