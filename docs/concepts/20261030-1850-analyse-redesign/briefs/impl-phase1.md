## Phase 1 — build now

1. **Chat flow, centred column** (max ≈ 780 px). Every stage is a vertical message flow: devops avatar (∞ glyph, tooltip "devops", no ring; only the CURRENT message glows) left; the user's own answer right-aligned (iMessage/WhatsApp convention), same column.
   A question stage = 3 separate messages entering one after another with a guiding "read me" glow (≈ 0.9 s enter, ≈ 1.8 s apart): finding → question → answer block. Animate only on the first visit of a stage; later visits instant; `prefers-reduced-motion` → none.
2. **Question message fixed height** (question + one "Davon hängt ab" line). Finding message and answer block have variable height; the answer block never pushes the question out of view (cap ≈ 45 % of the viewport, internal handling if larger).
3. **Finding message with tabs** "📊 Befund" / "🖥 Beispiel" (large icons, labels only, explanation in the app tooltip). Beispiel = a concrete case from the real application (screen excerpt / code / transcript), a diagram only when there is nothing visual. Switching the tab animates; messages below briefly fade out and back in. The highlighted part of a chart (`spec.hl`) pulses once. Contract: `data-example` slot inside the finding (L3 long → "Befund", new example slot → "Beispiel").
4. **Answer block** = raised surface (blue gradient + 1 px blue border), options as ROWS (radio/checkbox, label + consequence, "So sähe das aus" line), ★ Empfohlen chip, preselected. Text link under it: "Keine passt? Schreib deine Antwort unten ins Notizfeld." (sets `dm-{id}-none`, focuses the composer). Existing modes single/multi/slider/order/yesnoalt/verify/wording restyled to this look (rows, slider with ★ marker + live consequences, order list, Ja/Nein/Anders as 3 fields).
5. **Settled Q&A**: once the next question arrives, previous Claude messages + the user's answer turn calmer (outline instead of fill, smaller, dimmer) — NO check mark.
6. **Persistent composer** at the bottom of every analysis stage (incl. briefing + closing) = THE note field (replaces per-decision inline textarea visually; the per-decision `data-comment="{id}-note"` stays the storage target for the stage that is open). Single line, grows to max 3 lines; one-line hint only (no "Gilt für diese Seite"); 📎 inside; send button = clear, solid "send" arrow. Generous bottom/top clearance so nothing collides with concept chrome (☰, 💬, quick nav).
   **Tag**: max ONE tag, default none. Clicking a finding / question / topic (and the closing toggles) sets the tag; it renders as a small inline text-height label before the first word, with ×. A note sent WITH a tag stays on the stage; a note WITHOUT tag advances to the next stage (not on briefing / closing).
7. **Right rail TOC** (replaces the left/top stepper; keep the existing top quick-nav of concept pages untouched): dots on a hairline, no box. Fixed 18 px rows, scrollable (hidden scrollbar, soft fade top/bottom) when items exceed the height; every pixel belongs to an item (no gaps), `cursor: pointer`, click = go to stage. Hover: font of item under the mouse 14 px bold, ±1 neighbours 12.5 px, ±2 11.5 px, all others label-less; NO transforms that overlap. Topics carry a "THEMA" prefix in the item. Current item kept in view. Must stay clear of the ☰ / 💬 FABs (start below ☰, end above 💬).
8. **Stage peeking**: previous stage hinted above, next below (masked fade text), instead of separate navigation chrome.
9. **Page-type signatures**: Briefing + closing = cool blue family of devops concept (#58a6ff/#79c0ff/#a5d6ff/#388bfd), no own type colour, same layout family; Topic page = topic colour hero (strongly different hue per topic, chosen by Claude, never blue, never the note purple, never the concept variant colours, never red/green/orange status colours); question stages inherit their topic colour (left edge, meta label, chart). Hierarchy of visual weight: briefing > topic > question.
10. **Briefing**: eyebrow = the analysis title only (the concept's dropdown name when inside a devops concept); huge gradient number + unit; one smaller claim sentence; top-3 findings as cards in blue variations; bottom CTA row "N Fragen · [Los] · ≈ X min" with the button centred. Sequential reveal.
11. **Topic page**: "Thema n von N", title (≤ 5 words rule), conic ring with share of potential, the topic's questions as a numbered list, button. No "roter Faden" block — continuity lives in the first sentence of each finding ("Nach deiner Antwort zu … bleibt …").
12. **Closing**: blue like briefing; headline result; list of all questions/topics with a dwell bar and a per-row toggle button "Nachschärfen" (grey off / blue on), pre-set by the mechanism below; toggling ON makes the composer glow and sets the tag. Details of the signal only in the toggle's tooltip. Buttons "Jetzt umsetzen" (primary) / "Nächste Runde"; when the analysis is part of a devops concept and more entries follow, a link to jump there. No "alle Antworten", no duplicated counts.
13. **Hesitation signal (Phase 1 = data + preset)**: per decision record `hesitation: { ms, noteWords, revisits, flagged }` — ms counts only while the stage is visible AND the window focused (Page Visibility + focus/blur, timestamps, back-and-forth summed). Flag when ≥ 2 of: ms > 2× median of this analysis and ≥ 20 s; note > 12 words; ≥ 2 revisits/changes. Payload carries it; the closing toggles start from it. Consumers (next round / implementation) read it — document in step5-process: flagged → next round re-asks adapted, or if it is about the topic itself → into concept/implementation with special attention.
14. **Rules (authoring + gate)**: Full = 1–7 topics, 3–7 questions per topic (gate warns outside); topic titles ≤ 5 words; Ausgangslage (`data-situation`) stays required-ish (A9 warn). Remove evidence popups ("Belege") from the authoring rules — deeper detail is requested via a note.
15. Lite (≤ 5 questions inside another concept) uses the same chat flow without topic pages; no empty start stage.
