## Notes on the ✗ rows

- **S1.1**: the round-2 table shows `› Weiter in: Login-Fix` while the child works. The renderer prints a `Weiter in der Side-Session: „👉 ➜ ❓ Question ┃ X“` line only when the user's move is in that session (waiting/failed), as brief item 10 says; for a running child there is no line. Accepted deviation (brief wins), but not the table text.
- **S1.4 / S2.4 (ship-successful or released with the parent's OWN `delivery`)**: if the parent re-sends its own ship data, the heading is the parent's own release (`Released Alpha — v0.362.0 — nach Beta promoten?`), promote buttons for the own release stay, and the side session's shipment appears only as `› „X“ geshippt v…`. Without own delivery data (S1.4b/c, S2.4b/c) the heading is the spec one (`… in Side-Session „X“ geshippt, hier ist nichts offen`, no buttons). So the spec wording depends on how the model fills the card; not a renderer bug, but the tool description should say: for the final side-session-shipped card pass no `delivery`.
- **delivered with open point**: one button `Nachbessern` (a follow-up reply, not Ship) — fine.
- **S6 (nested)**: no card feature of its own: the middle session is simply a parent whose `linked` holds its children; row shows ⏳ Linked while they run. Its card toward the top chat is the model's call.
- **S2.2 (⏳ ➜ 🚀 Shipping)** is the normal ship-progress title, not a card; unchanged by this diff.
